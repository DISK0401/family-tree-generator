# family-tree-generator

日本市場向けWeb家系図作成サービス「家系図帖(かけいずちょう)」。個人開発・freemium。

## ページ構成

| パス | 内容 |
|---|---|
| `/` | 製品紹介(ランディング)ページ。未定義のパスもここへフォールバックする |
| `/app` | 家系図エディタ(このリポジトリの根幹機能) |
| `/app?sample=<id>` | 偉人家系図サンプルをエディタに読み込んで起動する(既存データがある場合は上書き前に確認) |

ランディングページは完全静的で、フォーム・解析タグ・外部リソース読み込みを一切持たない。エディタ(family-chart/D3を含むチャンク)はルート単位のコード分割によりランディング表示時には読み込まれない。

### 偉人家系図サンプル

ランディングの「サンプルで完成イメージを見る」から、以下の4パターンをエディタで開ける(`src/samples/`)。

| サンプルID | 題材 | 見せるパターン |
|---|---|---|
| `tokugawa-ieyasu` | 徳川家康 | 複数の配偶者(正室・継室・側室) |
| `natsume-soseki` | 夏目漱石 | 養子縁組(実父母と養父母) |
| `shibusawa-eiichi` | 渋沢栄一 | 死別後の再婚・旧字体表記「澁澤榮一」 |
| `modern-family` | 現代の家族(架空) | 三世代の記録・和暦⇄西暦 |

サンプルの人選は「故人であり、Wikipedia等で系譜が公知の人物」に限定し、実在の存命人物・皇室系譜は扱わない。架空サンプルにはその旨を明記する(`openspec/specs/sample-tree-gallery/spec.md` 参照)。

## 機能(無料版)

家系図を手作業で作成できる画面(このリポジトリの根幹機能)を提供する。

- **家系図の手動作成**: 空状態から最初の人物を追加し、選択中の人物のコンテキストアクション(「配偶者を追加」「子を追加」「親を追加」)から図の上で家族を育てていく。再婚・複数配偶者(同一人物が複数の婚姻関係を持つ)にも対応し、複数の婚姻は婚姻日の判明しているものから時系列順に表示される。
- **人物情報の編集**: サイドパネルで氏名(姓・名を別々に保持し正規化しない)・ふりがな・性別・生年月日/没年月日・メモを編集できる。日付は和暦・西暦(年月日表記・ハイフン区切り・区切りなし8桁数字のいずれも)のどちらで入力しても、入力と同時にもう一方の表記が表示される(例: 「昭和39年10月10日」「19641010」→「1964年10月10日」)。「頃」「以前」「以後」などの不確実な日付表現にも対応。フォームに未確定の変更がある状態で他の人物を選択しようとすると確認ダイアログを表示し、変更の破棄・保存のどちらかを選べる(確定操作はEnterキーでも実行できる)。
- **続柄の編集**: 子の続柄(実子・養子・継子・里子)を変更でき、養子は家系図上で破線の系線として表示される。実親・養親の両方が記録されている人物は、養親側を優先して系線を描画する。
- **婚姻・離婚イベントの編集**: 配偶者として属する家族ごとに、サイドパネルで婚姻日・離婚日(各+場所)を編集できる。日付は生年月日/没年月日と同じ和暦・西暦相互入力に対応し、入力してフォーカスを外すと確定操作なしに即座に反映される。婚姻ごとに削除もでき、削除前に失われる婚姻・離婚の記録と子の帰属の件数を提示する(人物そのものは削除されない)。
- **配偶者の後からの紐づけ**: 先に「親を追加」で登録した親のように、配偶者が登録されていない家族には、既存の人物を配偶者として設定できる。これにより、婚姻関係と親子関係が別々に記録されてしまった状態を1つの家族へまとめられる(その家族の子は候補に含まれない)。選んだ相手との家族が既にある場合は、両方の子と婚姻・離婚の記録を引き継いで1つの家族へ統合するため、同じ夫婦の家族が二重になったり子が分かれて記録されたりしない。継親・後妻を誤って子の親として記録しないよう、「配偶者を追加」による自動的な合流は行わず、常に利用者が明示的に選ぶ。
- **関係を決めずに先に人物を登録**: キャンバス左下の「人物を追加」から、誰の何として登録するかを決めないまま人物だけを追加できる。戸籍や過去帳を書き写す際に、系統の順ではなく紙面の順で氏名・生没日を入力していける。追加した人物はそのまま選択状態になり、続けて編集できる。
- **既存の人物を関係先に選ぶ**: 「配偶者を追加」「子を追加」「親を追加」のそれぞれで、新しい人物を作る代わりに既存の人物を選べる。既存の人物を子として紐づけられるため、養子縁組を後から記録することもできる。「親を追加」で選んだ人物に配偶者が1人だけ判明している場合は、その夫婦の家族の子として記録されるため、片方の親からだけ系線が伸びる状態にはならない。親が片方しか登録されていない人物にもう一方の親を選ぶ操作は、そうした状態を夫婦の子として記録し直す修復手段にもなる。候補には、その関係が成立しえない人物(自分自身・既にその関係が成立している人物・繋ぐと自分が自分の祖先になってしまう人物)は表示されない。いとこ同士の婚姻のように世代の矛盾がない関係は登録できる。
- **関係の解除と繋ぎ変え**: 人物を削除せずに、親子関係(続柄の欄)・配偶者としての所属(婚姻・離婚の欄)だけを外せる。「配偶者だったのに子として登録してしまった」といった取り違えを、入力済みの氏名・ふりがな・生没日・メモを失わないまま直せる。解除の前には、家族ごと失われる場合の婚姻・離婚の記録と子の帰属の件数、および解除後にその人物が図から外れる旨を提示する。直後のundoで復元できる。
- **図に現れていない人物の一覧**: 関係を持たない人物や、本体の家系から切り離された人物は既定の折りたたみ表示では図に描けないため、キャンバス下部の一覧に並べる。クリックすると通常どおり編集パネルが開く。該当する人物がいないときは表示されない(全体表示(家系ごと)・つながった全体表示では全員が図に現れるため、一覧自体が出ない)。
- **自動整列と縦書き表示**: 自動レイアウトで、人物追加のたびに図全体が視界に収まるよう再整列する(折りたたみ表示・全体表示(家系ごと)は [family-chart](https://github.com/donatso/family-chart)、つながった全体表示は自前のレイアウタによる)。人物カードの氏名は縦書き・明朝体で表示し、性別を色と形状(男=四角・女=丸・不明=破線ひし形)で、生年月日が判明していれば現年齢(故人は没年齢)も表示する。
- **3つの表示の切り替え**: キャンバス左下で、次の3つを切り替えられる。
  - **折りたたみ表示**(既定): クリックのたびに視点が移動し、その人物から辿れる範囲を表示する。編集の主たる作業面。選択中の視点から辿れない範囲に人物がいるカードには人数バッジが表示され、クリックするとそちら側へ視点を切り替えて確認できる。どの人物からも辿れず視点の切り替えでは到達できない人物は、バッジではなく「図に現れていない人物」の一覧に並ぶ。
  - **全体表示(家系ごと)**: 折りたたみを止め、記録されている全員を漏れなく表示する。血縁でつながる家系ごとにブロックが分かれ、複数の親家族を持つ人物(実親・養親の両方が記録されている人物など)は、それぞれの家系の下にカードが複製されて現れる。
  - **つながった全体表示**: 婚姻も「つながり」として扱い、全員を1枚の連結した図に表示する。夫の実家と妻の実家のように婚姻でしかつながらない血族どうしも、家系ごとに分かれず1枚に収まる。同じ人物のカードが複製されることはなく、実親・養親の双方を持つ人物には両方の親家族から系線が引かれる(養子側は破線)。
- **人物一覧の表(表形式ビュー)と Excel ライク編集モード**: 画面上部の「図 / 表」で切り替えると、登録されている全人物を1行1人の表で一覧できる。列は右側パネルで編集できる項目(姓・名・ふりがな・性別・生没年月日・生没地・メモ)+閲覧用の配偶者名。**列見出しからすべての列を並べ替えでき**(押すたびに昇順→降順→解除。未入力の値は常に末尾)、**列見出しの直下の欄で列ごとに絞り込める**(性別は選択式、それ以外は部分一致。複数列を指定すると全条件を満たす行だけが残る)。生年月日・没年月日の絞り込みは表示中の書式に縛られず、**和暦でも西暦でも(「平成6年10月01日」「1994-10-01」「19941001」いずれでも)同じ人物がヒットする**。「1994」「平成6年」のように年だけ、「1960〜1965」のように範囲でも絞れる。氏名・ふりがなを横断して探す検索欄も別にあり、絞り込みは「絞り込みを解除」で一括して戻せる。「編集」モードに切り替えると表計算ソフトのように使える。
  - セルを直接編集でき、Enterで下・Tabで右へ移動する(日本語入力の変換確定は誤ってセル移動にならない)。日付セルは和暦・西暦・8桁数字を通常の入力欄と同じように解釈する。
  - **Ctrl+C / Ctrl+V** でセル範囲をコピー・貼り付けできる。形式は Excel・Google スプレッドシートと同じ(タブ区切り)なので、表計算ソフトで下書きした名簿を範囲選択してそのまま貼り付けられる(セル内の改行を含むメモも1セルとして往復する)。
  - 表の末尾の行に入力すると**人物を追加**できる。貼り付けた行数が既存の人数を超えた場合も、超過分が新しい人物として追加される。追加した人物は関係を決めずに登録した扱いで、続柄や配偶者は図・パネル側で結ぶ。
  - 貼り付けた範囲に解釈できない値が混ざっていても、読めたセルはそのまま取り込み、取り込めなかったセルは行と列を示して知らせる。貼り付け全体は「元に戻す」1回でまとめて取り消せる。
  - 人物の削除と関係(親子・配偶者・続柄・婚姻)の編集は、影響範囲を確認できる図・パネル側の操作に限定している(表からは行えない)。
- **表示設定**: 設定メニューから、人物カードに表示する生年月日・没年月日の粒度(年のみ/年月まで/年月日まで)、表示形式(西暦/和暦)、表示する項目(姓・名・ふりがな・生年月日・没年月日・出生地・没地・年齢・性別アイコンを個別にオン/オフ。例: 姓を非表示にして名だけ表示する)を選べる。あわせて「婚姻日(線)」をオンにすると、配偶者を結ぶ婚姻線にその家族の婚姻日を表示できる(離婚日は表示されず、表示形式の西暦/和暦設定に追従する)。端末ローカルの表示設定であり、GEDCOM/JSONのエクスポート内容には影響しない。
- **人物の削除**: 削除前に影響範囲(配偶者関係・子の帰属の件数、家族ごと削除される場合は失われる婚姻・離婚の記録の件数)を提示して確認を求める。配偶者を削除した結果、配偶者が1人だけで子もいない家族が残ることはない(そうした家族は婚姻単位としても親子関係の器としても成立しないため、あわせて削除される)。誤操作は直後のundoで復元できる。
- **データの全削除**: 端末内のすべての家系図データを、確認フレーズの入力を伴う操作で完全に削除できる。
- **GEDCOM/JSONのインポート・エクスポート**: 設定メニュー(画面右上の「⋯」)から、GEDCOM 7.0・GEDCOM 5.5.1互換・アプリ独自JSON形式でのデータの読み込み・書き出しができる。エクスポートファイル名にはタイムスタンプ(`yyyyMMddHHmmss`)が付与され、複数回書き出しても既存ファイルを上書きしない。詳細は下記「GEDCOM / JSON インポート・エクスポート」を参照。

PDF/巻物出力、戸籍スキャンからの自動生成(有償版)などは今後の変更で実装予定。

## プライバシー方針(無料版)

**無料版は家系図データ・個人情報を一切サーバーへ送信しない。** すべてのデータはブラウザのIndexedDBに保存され、この端末の外に出ることはない(検証方法は[開発者向け情報](#開発者向け情報)を参照)。この約束は Content-Security-Policy(`connect-src 'self'` ほか。`worker/index.ts` が全レスポンスへ付与)によりブラウザレベルでも強制されており、仮に将来のコード変更で外部リクエストが紛れ込んでもブラウザが遮断する。

- 保存先は常に画面ヘッダーに明示される(「この端末にのみ保存されます」)。
- ブラウザを再訪すると、直前の編集内容が自動的に復元される。
- 「すべてのデータを削除」から、端末内のデータをいつでも完全に消去できる。

## セットアップ

Node.js **22 以上**を使用する(`.nvmrc` / `package.json` の `engines` を参照。CI も同じ値を読む)。

```bash
npm install
npm run dev
```

`http://localhost:5173` で製品紹介ページが、`http://localhost:5173/app` で家系図作成画面が表示されます。

Windows・macOS・Linuxいずれの環境でも、追加のコマンド実行なしに `npm install` のみでセットアップが完了する(ビルドツールが要求するプラットフォーム固有のネイティブバイナリは、ルート `package.json` の `optionalDependencies` に主要プラットフォーム分を明示しているため、ロックファイルの生成環境によらず解決される)。

## GEDCOM / JSON インポート・エクスポート

無料版はクライアント(ブラウザ)完結で動作し、家系図データ・個人情報を一切サーバーへ送信しない。ファイルの読み込み・書き出しはすべてブラウザ内の処理のみで完結する(画面右上「⋯」の設定メニュー内「GEDCOM/JSONの読み込み・書き出し」から操作する)。

### 対応フォーマット

| フォーマット | インポート | エクスポート | 用途 |
|---|---|---|---|
| GEDCOM 7.0 | ○ | ○(推奨) | 養子縁組・事実婚など複雑な家族関係まで表現できる最新規格 |
| GEDCOM 5.5.1互換 | ○ | ○ | 他の家系図サービス(MyHeritage 等)への移行に適した従来規格 |
| JSON(アプリ独自形式) | ○ | ○(完全バックアップ) | 内部データ(`TreeDocument`)をロスレスに保存・復元する独自形式 |

- GEDCOMのバージョン(7.0 / 5.5.1)はファイルヘッダから自動判定する。
- 文字コードは UTF-8(BOM有無とも)・UTF-16・Shift_JIS(国産ソフト由来ファイル対策)を自動判定して読み込む。
- インポート結果は人物数・家族数・判定した文字コード・警告一覧を平易な日本語でサマリ表示する。警告があってもインポート自体は成立する。
- すでにデータがある状態でインポートすると、既存データを置き換える旨の確認を経てから反映される(undo/redo履歴はインポート時にクリアされるため注意)。
- 氏名・続柄・関係種別・日付は `docs/gedcom-mapping.md` の対応表に従ってGEDCOMタグへマッピングされる(ふりがなは拡張タグ `_KANA_SURN`/`_KANA_GIVN`、事実婚等の関係種別は拡張タグ `_FAM_KIND`)。

### 制限事項

- **GEDCOMの非標準タグを汎用的に保全する機能はない。** 対応表(`docs/gedcom-mapping.md`)にないGEDCOM情報(出典・メディア参照等)は、警告を出したうえで安全に読み飛ばされる。完全な往復保存が必要な場合はJSON形式を利用すること。
- **GEDCOM ANSELエンコーディングは非対応。** 検出時はインポートを中断し、UTF-8で再エクスポートしたファイルの利用を案内する。
- **インポートファイルのサイズ上限は20MB。** 超過時は読み込み前に明示的なエラーとする。
- **婚姻取消(ANUL)は離婚として取り込まれる。** 内部データモデルに婚姻取消専用の種別がないための制約。
- **3名以上のパートナーを持つ家族のGEDCOM出力は非標準表現になる。** 再インポート時に3人目以降が失われる可能性がある(JSON形式では問題なく保存できる)。

## 開発者向け情報

### アーキテクチャ

- `src/domain/`: 家系図のドメインモデル(Person・Family・和暦変換等)。フレームワーク非依存の純関数群。
- `src/store/`: Zustandによる状態管理。コマンド適用+undo/redo。
- `src/persistence/`: IndexedDB(`idb`)への自動保存・復元・スキーマバージョンガード。
- `src/layout/`: 「つながった全体表示」用の自前レイアウトエンジン(世代割当・層内順序・座標・系線)。フレームワーク非依存の純関数群。
- `src/rendering/`: family-chartによる家系図描画。ドメインモデルをfamily-chart形式へ射影するアダプタ層を介する(family-chart側のデータを保存・編集の正本にしない)。
- `src/lib/gedcom/`: GEDCOM 7.0/5.5.1の構文層(パーサ/シリアライザ)・意味層(氏名/日付/続柄/家族関係種別マッピング、インポート/エクスポート)。
- `src/lib/json/`: アプリ独自JSON形式(`TreeDocument`直列化)の入出力・zodスキーマ検証。
- `src/features/import-export/`: ファイル入出力のユーティリティ(サイズ上限、エクスポートファイル名の生成等)。
- `src/features/person-table/`: 表形式ビューの列定義(表示文字列の導出とセル文字列の解釈)とTSVクリップボードの直列化・パース。描画に依存しない純関数群。
- `src/settings/`: 表示設定(日付粒度・和暦/西暦・カード表示項目)のストアとUI。端末ローカル(localStorage)保持。
- `src/components/`: 編集UI(サイドパネル、日付入力、確認ダイアログ、インポート/エクスポート等)。
- `src/pages/`: 製品紹介(ランディング)ページと図版(トークン準拠の軽量SVG。family-chart非依存)。
- `src/samples/`: 偉人家系図サンプルのデータ(`TreeDocument`形式)と `/app?sample=<id>` 読み込み処理。データ本体はエディタ側チャンクから動的importされる。
- `src/routes.ts` / `src/Root.tsx`: パス判定によるランディング/エディタの出し分けとルート単位のコード分割(ルータライブラリ不使用)。
- `worker/`: Cloudflare Workers のエントリ。静的アセット配信に加え、セキュリティヘッダ(CSP等)の付与・ハッシュ付きアセットの immutable キャッシュ・非本番環境への noindex を担う。
- `spike/`: family-chart の挙動検証スパイク(凍結・ビルド非含有)。詳細は `spike/README.md`。
- `docs/gedcom-mapping.md`: 内部データモデルとGEDCOM 7.0タグの対応表(GEDCOM入出力の実装リファレンス)。

設計判断の詳細は `openspec/changes/*/design.md` を参照。

### 外部送信ゼロの検証方法

無料版の「サーバへ一切送信しない」制約は、三層で守られている。

1. **E2Eテスト(CI)**: `npm run test:e2e` が実ブラウザでランディング・エディタ操作・サンプル読み込みの全リクエストを監視し、自オリジン以外へのリクエストが0件であることをアサートする(`e2e/no-external-requests.spec.ts`)。
2. **CSP(本番)**: `worker/index.ts` が全レスポンスへ `connect-src 'self'` 等の Content-Security-Policy を付与し、仮に外部リクエストが混入してもブラウザが遮断する。
3. **手動確認**: ブラウザの開発者ツールのネットワークタブでも同様に確認できる。

### OGP画像の運用

`public/ogp.png`(1200×630)はSNS共有用の1枚絵で、テーマには追従しない。デザイン刷新時は `docs/assets/ogp-source.html` を編集して再生成する。

```bash
npm i --no-save playwright-core @fontsource/noto-serif-jp @fontsource/noto-sans-jp
# docs/assets/ogp-source.html を 1200x630 でスクリーンショットして public/ogp.png へ保存する
# (playwright-core の chromium.launch → page.goto(file://...) → page.screenshot)
```

`index.html` の `og:image` / `og:url` / `canonical` は workers.dev 本番URLの絶対URLを指す(主要SNSのスクレイパは相対パスを解決しないため)。カスタムドメイン確定時に張り替える。

## ブランチ運用とデプロイフロー

`feature/* → develop → main` の順でマージする。

- `develop` へのマージ: Cloudflare Workers 上の **dev 環境** へ自動デプロイ
- `main` へのマージ: Cloudflare Workers 上の **本番環境** へ自動デプロイ

デプロイは `.github/workflows/deploy.yml` から `wrangler deploy` を実行して行われる。`develop` / `main` への Pull Request では `.github/workflows/quality-gate.yml` が lint・フォーマット・型チェック・テスト・ビルドを実行し、失敗時はマージをブロックする(必須チェック名はジョブID `quality`)。deploy 側でもデプロイ前にテストを再実行する — Quality Gate はPRのマージ前コミットに対して走るため、個別には緑な2つのPRを続けてマージした際の「マージ結果」を検証する最後の防壁がこれにあたる。

開発フローは OpenSpec change(`openspec/changes/<name>/`)を起点に proposal → design → tasks → 実装 → verify → archive の順で進める(`openspec/config.yaml` と `.claude/commands/opsx/` を参照)。ブランチ運用の詳細は `CLAUDE.md`。

Cloudflare の設定は可能な限りコードで管理している。

- Worker 本体・dev/本番の環境定義: `wrangler.jsonc`
- デプロイ実行・ブランチ連動: `.github/workflows/`
- カスタムドメインなど Cloudflare アカウント/ゾーンレベルのリソース: [my_infra](https://github.com/DISK0401/my_infra) リポジトリの Terraform で管理(PR → Speculative Plan 確認 → `main` マージ → `/apply` コメントで apply)

コードで管理できない初回セットアップ作業(Cloudflare API トークン発行、GitHub Secrets 登録など)は [`docs/setup/cloudflare-manual-setup.md`](docs/setup/cloudflare-manual-setup.md) を参照。

## ロールバック

- **本番デプロイの巻き戻し**: `wrangler rollback --env production` を実行するか、直前の正常なコミットを `main` に revert して再デプロイする。
- **dev 環境**: `develop` へマージしなければ本番には影響しないため、問題が見つかった場合は `main` へのマージを見送る。

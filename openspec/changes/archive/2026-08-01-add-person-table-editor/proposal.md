# add-person-table-editor

## Why

現在の入力インタフェースは「図の上で人物を選び、右側パネルで1人ずつ編集する」形に限られる。1人あたりのフィールド数は多く(姓・名・ふりがな・性別・生没年月日・生没地・メモ)、戸籍や過去帳から数十人を書き写す用途では、選択→パネル→確定の往復が入力の大半を占めてしまう。「関係を決めずに先に人物を登録」(キャンバス左下の「人物を追加」)で紙面の順に登録していく流れは既にあるが、その後の属性入力は依然として1人ずつである。

市場調査(`docs/research/2026-07-market-ux-legal.md`)では、家系図づくりの現場で **Excel が入力面の事実上の競合**であることが示されている(「Excel等は人物追加のたびに線を引き直す苦痛」— 裏を返せば、表形式の入力体験そのものは支持されている)。また競合サービス共通の不満として「操作性」「和暦/旧字体入力の煩雑さ」が挙がっている。本アプリは線の自動整列と和暦⇄西暦相互入力を既に持つため、**表形式の閲覧+Excel ライクな一括編集**を加えれば、「Excel の入力しやすさ」と「専用アプリの描画・整列」を1つで提供でき、差別化軸(UX)を直接強化する。

あわせて、表形式の一覧は校正にも効く。図(カード)は関係の把握には強いが、「没年月日が未入力の人物はどれか」「ふりがなの入れ漏れはないか」といった**属性の抜け漏れの走査**には表が適している。

影響範囲は**無料版のみ**。クライアント完結の UI 追加であり、有償版・サーバ通信・戸籍データの流れには一切関与しない。

## What Changes

### 1. 人物一覧の表形式ビューを新設する

登録されている全人物を1行1人の表で閲覧できるサポート画面をエディタ内に追加する(図と切り替え、または併置。配置は design で決める)。

- 列は、右側パネル(人物編集フォーム)で参照/変更できる人物属性を基本とする: 姓・名・姓(ふりがな)・名(ふりがな)・性別・生年月日・出生地・没年月日・没地・メモ。
- 生没年月日は表示設定(和暦/西暦・粒度)に追従して表示する。
- 並べ替え(例: 氏名・生年月日)と、氏名・ふりがなによる絞り込みを提供する(校正用途)。
- 行を選ぶと該当人物が図・パネル側でも選択される(既存の選択導線と整合)。
- 関係情報(配偶者・親など)は行=人物の表に素直に載らないため、閲覧用の**読み取り専用の要約列**(例: 配偶者の氏名)として design で検討する。表からの関係編集は行わない(Non-Goals 参照)。

### 2. Excel ライクな編集モードへ切り替えられる

表形式ビューは「閲覧モード」と「編集モード」を明示的に切り替えられる。編集モードでは:

- **セル編集**: クリック(または F2/直接入力)でセルを編集し、Enter/Tab/矢印キーで隣のセルへ移動できる。
- **コピー&ペースト**: Ctrl+C / Ctrl+V でセル・矩形範囲のコピー&ペーストができる。クリップボードは TSV 互換とし、**Excel・Google スプレッドシートとの相互貼り付け**を成立させる(Excel で下書きした名簿を範囲選択して貼るだけで取り込める)。
- **人物の追加**: 表の末尾で新しい行を追加できる。追加された人物は「関係を決めずに登録した人物」と同じ扱い(関係リンクは図・パネル側で後から結ぶ)。複数行のペーストが既存行数を超える場合も、超過分を新規人物として追加する。
- **日付セルの和暦⇄西暦相互解釈**: 既存の日付パーサ(「昭和39年10月10日」「1964-10-10」「19641010」「頃/以前/以後」)をセル入力・ペースト双方に適用する。解釈できない値は取り込まずにセル単位でエラー表示し、どの行・列が弾かれたかを明示する。
- **undo/redo との統合**: 表での編集(ペーストによる一括変更を含む)は既存の undo 履歴に乗り、**1回のペースト=1回の undo** で丸ごと戻せる。
- 編集は既存のドメインコマンド(updatePerson / addPerson)を通し、図・パネル・自動保存と同じデータフローに乗せる(表専用のデータ経路を作らない)。

### 3. 競合水準の確保

- 「みんなの家系図」等の国内競合は表形式の一括編集を持たず、フォーム入力の操作性不満が報告されている(調査資料 §1)。本変更はそれらの**上位互換の入力体験**を狙う。
- 汎用ツール(Excel/スプレッドシート)との比較では、①貼り付け互換(TSV)で乗り換えコストを消し、②和暦相互解釈・自動整列・GEDCOM 出力という表計算にない価値を残す。

### Non-Goals

- **関係(親子・配偶者・続柄・婚姻/離婚)の表からの編集**。行=人物の表に多対多の関係編集を載せると破綻しやすく、既存の図+パネルの導線(影響予告つき)が適している。将来の拡張余地としては残す。
- **人物の削除を表から行うこと**。削除は影響範囲の予告(配偶者関係・子の帰属・失われる記録の件数)を伴う既存導線に限定する。
- **CSV ファイルのインポート/エクスポート**。クリップボード経由の貼り付けで当面の用途を満たす。ファイル交換は既存の GEDCOM/JSON を正とする(将来 CSV を足す場合も本機能とは別 change)。
- **モバイルでの編集モード最適化**。閲覧は成立させるが、矩形選択やキーボード操作はデスクトップ前提とする(モバイルは「閲覧可能レベル」という既存方針に従う)。

## Capabilities

### New Capabilities

- `person-table-editor`: 登録済み人物の表形式ビュー(閲覧モード: 一覧・並べ替え・絞り込み・選択連動)と、Excel ライクな編集モード(セル編集・キーボード移動・TSV 互換の Ctrl+C/Ctrl+V・行追加による人物追加・日付の和暦⇄西暦解釈・一括操作の undo 統合)。

### Modified Capabilities

(なし — 表の編集・人物追加は既存のドメインコマンドと自動保存の要求をそのまま満たす形で実装し、`tree-editor`・`local-autosave` 等の既存要求は変更しない。実装中に既存 spec の要求変更が必要と判明した場合は、その時点で本 proposal を更新して delta spec を追加する)

## Impact

- **プライバシー・法務**: 影響なし。クライアント完結の UI 追加のみで、データの保存先(IndexedDB)・外部送信ゼロの方針・CSP(`connect-src 'self'`)は不変。クリップボード操作はブラウザ内で完結する(ペースト内容はユーザー自身の操作でのみ取り込まれる)。戸籍データの流れの変更もない。
- **コード**: `src/components/`(表ビュー・編集モードの新規コンポーネント群)、`src/App.tsx`(表示切替の導線)、`src/store/` / `src/domain/`(既存コマンドの再利用が基本。「複数セルの一括更新を1 undo 単位にする」バッチ適用が必要になる場合はコマンド層に薄い追加)。図(`src/rendering/`)・永続化(`src/persistence/`)・入出力(`src/lib/`)は変更しない。
- **依存**: 追加ライブラリを入れる場合は、外部送信ゼロ制約(CDN 不使用・自己ホスト)とライセンスを満たすものに限る(候補: ヘッドレスの TanStack Table 等)。矩形コピー&ペーストは TSV のクリップボード処理を自前で持つ想定。採否は design で決める。
- **テスト**: セル編集・ペースト解釈(正常/エラー混在)・行追加・undo 統合のコンポーネントテストを追加。E2E スモーク(外部送信ゼロ)は既存のまま通ることを確認。
- **README**: 機能一覧(無料版)への追記を実装タスクに含める。

## ロールバック方針

UI コンポーネントと切替導線の追加のみで、**データモデル・保存形式・入出力形式の変更を伴わない**。問題発生時は表ビューへの導線を外す(または change を revert する)だけで既存機能へ影響なく戻せる。表で入力されたデータは通常のドメインコマンド経由で書かれた通常のデータであり、ロールバック後もそのまま有効。

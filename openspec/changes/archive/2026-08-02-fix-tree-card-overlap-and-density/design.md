## Context

人物カードは `src/organisms/tree-canvas/person-card.ts`(HTML組み立て)と `person-card.css`(見た目)が、折りたたみ表示(`FamilyTreeCanvas.tsx`, family-chart)・つながった全体表示(`PedigreeCanvas.tsx`, SVG)の両方から共有されている。カード寸法(`CARD_SIZE = { width: 104, height: 116 }`, `src/layout/coordinates.ts`)は表示設定と無関係な固定値で、世代間隔・兄弟間隔などレイアウト計算全体の前提になっている。

直近の類似修正(`2026-07-30-fix-card-display-and-focus` design.md D1/D2)で、姓・名の縦書き列については「`white-space: nowrap` で折り返しを禁止 + 文字数に応じたフォント縮小(下限あり)」という対策を導入済み。今回の3件の不具合は、この対策が及んでいなかった箇所(ふりがな行・アイコンの絶対配置・カード寸法そのもの)で同種の問題が表面化したものである。

- **データフロー**: 本変更はカードの見た目(HTML構造・CSS・レイアウト計算の定数)のみを扱う。データの生成・保存・送信経路(IndexedDB / Supabase / Gemini API)には一切触れないため、データフロー図・RLSポリシー・外部送信データの検討は対象外(現状維持)。

## Goals / Non-Goals

**Goals:**
- ふりがな・氏名・生没年月日・年齢・生没地・性別アイコン・故人マーカー・非表示人数バッジのいずれの組み合わせでも、要素同士が視覚的に重ならないこと
- 戸籍由来の伝統的な3文字までの氏名(例:「仁三郎」「武之助」)が、表示項目を全てオンにした状態でも縮小されずに表示されること
- 全項目表示時にも、各要素間に最低限の余白が確保され「ギチギチ」に見えないこと

**Non-Goals:**
- 生年月日・没年月日のフォーマット自体(和暦/西暦の区切り方、粒度)の変更
- `visibleCardFields` の項目構成自体の変更(項目の追加・削除)
- レイアウトアルゴリズム(世代割り当て・結合点処理など、`pedigree-layout`capability)自体の変更。`CARD_SIZE` という「定数」を変えるだけで、間隔計算のロジックには手を入れない

## Decisions

### D1: 性別アイコンと故人マーカーを隣接配置にし、カードの`padding-top`でコンテンツ開始位置を一括して下げる

現状、性別アイコン(`top/left: 4px`)と故人マーカー(`top/right: 4px`)はそれぞれ独立してカード四隅に絶対配置されており、ふりがな行(先頭フロー要素)はカードの`padding-top`直後(8px)から始まるため、文字数が多いと性別アイコンと重なる(不具合1)。また故人マーカーは非表示人数バッジ(`top:-8px; right:-8px`)と同じ右上領域を取り合って衝突する(不具合3)。

対策として:
- 故人マーカーを性別アイコンの右隣へ移動する(`left: 18px`前後 = 性別アイコン幅10px + 間隔4px + 性別アイコンのleft4px。実測して微調整)。`top`は性別アイコンと視覚的に中心が揃う値に調整する
- これにより右上絶対配置領域は非表示人数バッジ専用になり、不具合3は構造的に解消する
- `.tree-card`の`padding-top`を、性別アイコン・故人マーカーの縦幅(実測12px程度)+余白ぶんだけ増やす(現8px → 24px程度、`--space-5`)。ふりがな表示の有無に関わらずカードの最初のフロー要素(ふりがな行、非表示時は氏名列)は常にこの新しい`padding-top`から始まるため、アイコンの有無や文字数に関係なく重なりが構造的に起きなくなる

*代替案*: ふりがな行だけに`margin-top`を足す → ふりがな非表示設定時は氏名列が先頭要素になるため、同じ配慮を2箇所に重複して持つ必要がある。`.tree-card`の`padding-top`を一箇所で持つ方が、「どの要素が先頭に来ても必ずアイコンの下から始まる」という不変条件をシンプルに保てる

### D2: ふりがな行に、氏名列と同様の「文字数に応じたフォント縮小(下限あり)+ nowrap + ellipsisフォールバック」を追加する

`nameFontScale`(氏名列用、`COMFORTABLE_CHARS=2`)とは別に、ふりがな用の縮小関数を用意する。ふりがなは「姓かな + 半角スペース + 名かな」の1行の横書きテキストで、氏名の縦書き列とは行の向き・利用可能幅が異なるため、しきい値も個別に決める。

自社サンプル(`src/samples/data/shibusawa-eiichi.ts`)の「しぶさわ たけのすけ」(9文字)、実機報告の「かわしまじんさぶろう」(10〜11文字相当)を、カード幅拡大後(D3)も縮小なしで1行に収められることを目安に、無縮小しきい値`KANA_COMFORTABLE_CHARS`を10文字に設定した(実測で「かわしま じんさぶろう」(11文字)がscale≈0.91で1行に収まることを確認)。下限`MIN_SCALE`は氏名列と同じ0.6とする。

縮小の下限に達してもなお収まらない極端な入力(数十文字のふりがな等)への保険として、`white-space: nowrap` に加えて `overflow: hidden; text-overflow: ellipsis`(`.tree-card-places`と同じパターン)を併用する。折り返しによる行数増加(→カード高さの逼迫)を構造的に防ぎつつ、無限に小さくなる/枠外にはみ出すことを避ける。

**実装中に発見した問題**: 氏名列(`nameColumnHtml`)の縮小は`font-size: {scale}em`というインラインスタイルで実現している。しかし`font-size`プロパティの`em`単位は常に**親要素**の実フォントサイズを基準に解決される仕様のため、「クラス自身の元のfont-size」を基準に縮小されるとは限らない。氏名列はクラスの元のfont-size(`--text-md`=1rem=16px)が祖先要素の実フォントサイズ(既定16px)とたまたま一致していたため正しく縮小されていたが、ふりがな行の元のfont-size(0.5625rem=9px)は祖先のfont-sizeと一致しないため、同じ手法だと逆に(16px基準で)拡大されてしまうことが実測で判明した。ふりがな側は絶対値の`rem`(ルート要素基準で祖先のfont-sizeに依存しない)で計算するよう実装した。氏名列側は現状で正しく機能しているため、今回のスコープでは変更しない

*代替案*: 縮小せず`.tree-card-places`と同様にellipsisのみで対応 → ふりがなは読み仮名という性質上、途中で切れると意味を失いやすい。氏名列と同じ「まず縮小、それでも駄目なら省略」という段階的対応の方が実用性が高い(1回目の探索での合意方針)

### D3: `CARD_SIZE`を拡大し、`nameFontScale`の`COMFORTABLE_CHARS`を2→3に引き上げる

現行寸法(104×116px)では、姓・名それぞれ3文字(戸籍由来の伝統的な名によくある長さ)を等倍表示しようとすると、ふりがな・生没年月日・年齢・生没地を同時表示した際に物理的に収まらない。

- **幅**: 104px → 136px。生没年月日(和暦・full粒度で最長になるケース、例:「明治45年5月1日 – 昭和59年5月13日」)が実測で136px以上から折り返し行数が減る閾値のため、この値を採用した。生没地の表示域(ellipsisで切れる前に見える文字数)もあわせて広がる
- **高さ**: 116px → 180px。実装中に、氏名列(`.tree-card-name-row`)が`flex:1; min-height:0`で「余った分だけ」割り当てられる設計だと判明した。ふりがな・生没年月日・生没地をすべて表示し、かつ姓・名がともに3文字(無縮小しきい値の上限)という最も厳しい組み合わせを実際にブラウザでレンダリングして計測したところ、氏名列に必要な高さ(3文字・letter-spacing込みで約55px)に対し、他の行(ふりがな・生没年月日・生没地)が必要とする高さを差し引いた残りが不足し、**氏名の縦書きテキストが下の生没年月日へ実際にはみ出して重なる**ことを確認した(`min-height:0`は箱の縮小は許すが、`white-space: nowrap`のテキスト自体は縮まないため、はみ出しが視覚的に発生する)。この最も厳しい組み合わせで実測した必要高さ(約172px)に、行間の余白ぶん(後述のgap拡大)を足した値として180pxを採用した
- `nameFontScale`の`COMFORTABLE_CHARS`を2→3に変更する。3文字以下は等倍、4文字以上から文字数に反比例して縮小する(現行ロジックの閾値のみ変更、縮小の計算式自体は変更しない)
- `.tree-card`の行間(`gap`)を`--space-1`(4px)→`--space-2`(8px)に、下端パディングも同様に広げ、全項目表示時にも視認できる余白を確保する(Goals「ギチギチに見えないこと」に対応)

`CARD_SIZE`は世代間隔・兄弟間隔などレイアウト計算全体の前提のため、この変更で家系図全体の縮尺・カード間隔が変わる(意図した副作用)。データ自体(`TreeDocument`)は不変で、座標計算の結果のみが変わる。

*代替案*: `visibleCardFields`に応じて`CARD_SIZE`を可変にする(表示項目が少なければカードも小さくする) → レイアウトエンジン(`coordinates.ts`, `layout/index.ts`)が現在「カード寸法は固定値」という前提で書かれており、可変化は影響範囲がレイアウトエンジンとその大量のテスト(`coordinates.test.ts`等)まで広がる。今回は「全項目表示時でも破綻しない固定寸法」を確保することを優先し、可変化は将来の別changeの検討事項とする(スコープ外)

## Risks / Trade-offs

- [`CARD_SIZE`拡大により、表示項目を絞っている既存ユーザーの家系図が意図せず「間延び」して見える] → 幅・高さの拡大幅を必要最小限(氏名3文字+全項目表示時に破綻しない範囲)に留める。過大な拡大はしない
- [かなの`MIN_SCALE`まで縮小しても収まらない極端な入力でellipsis表示になり、読み仮名として不完全になる] → 実用上想定される戸籍由来の氏名・ふりがな長(概ね10文字前後まで)は無縮小〜縮小で収まる設計とし、それを超える極端なケースのみ省略される仕様として許容する
- [`coordinates.test.ts`等、`CARD_SIZE`定数に依存する既存テストの期待値がずれる] → 該当テストの期待値を新定数に合わせて更新する(tasksで洗い出す)
- [性別アイコンOFF設定時、故人マーカー単独の左詰め位置に空白ができ不自然に見える可能性] → 実装時にスクリーンショットで確認し、必要なら性別アイコン非表示時は故人マーカーを詰める調整を行う(Open Questions参照)

## Migration Plan

データモデル・保存形式(IndexedDB, GEDCOM/JSON)の変更を伴わない、見た目とレイアウト計算定数のみの修正のため、特別な移行手順は不要。通常のコミット単位でのデプロイ・ロールバック(revert)で対応する。`CARD_SIZE`変更のみを切り戻せば、既存データの座標計算も旧寸法へそのまま戻る。

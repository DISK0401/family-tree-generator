# add-standalone-person-and-relink

## Why

現在の編集モデルは「人物の作成」と「関係の作成」が常に一体になっている。`addSpouse` / `addChild` / `addParent`(`src/domain/commands.ts:53,68,138`)はいずれも**人物を新規作成しながら同時に線を引く**コマンドで、単独の人物を追加する `addPerson` の UI 呼び出し口は空状態ガイド(`src/components/EmptyStateGuide.tsx:23`)にしかない。この結果、次の2つの使い方ができない。

1. **先に人物を登録しておき、後から繋ぐ** — 戸籍や過去帳を書き写す場面では、系統の順ではなく紙面の順に人名が並ぶ。いま人物を登録するには必ず「誰の何として」を先に決めなければならず、書き写しの手が止まる。
2. **役割の取り違えを修正する** — 「配偶者だったのに『子を追加』で作ってしまった」という誤登録を直す手段が存在しない。関係を外すコマンド(`unlinkChild` / `unlinkSpouse` 相当)が1つもないため、唯一の復旧手段は**人物ごと削除して作り直す**ことであり、入力済みの氏名・ふりがな・生没年・メモがすべて失われる。undo の射程を外れた後(再訪後など)に気づいた場合は特に痛い。

2 は入力済みデータの喪失を伴うため、体験上の損失が大きい。調査(`docs/research/2026-07-market-ux-legal.md:15`)が挙げる共通の不満「⑥複雑な家族関係(養子縁組・再婚・複数配偶者)が描きにくい」も、関係を後から組み替えられないことが一因である。

影響範囲は**無料版のみ**。クライアント完結の編集ロジックと描画の変更であり、有償版・サーバ通信・戸籍データの流れには一切関与しない。

## What Changes

### 1. 人物の作成と関係の作成を分離する

- **単独の人物を追加する導線を追加**: 人物が1人以上ある状態でも、関係を指定せずに人物だけを追加できるようにする。既存の `addPerson` コマンドをそのまま使う。
- **既存の人物を関係先に選べるようにする**: 「配偶者を追加」「子を追加」「親を追加」のそれぞれに「既存の人物から選ぶ」経路を設ける。ドメイン側に以下を新設する。
  - `linkSpouse(A, B)` — 既存の2人を配偶者とする**新しい** Family を作る。既存の `addSpouseLink`(配偶者未登録の既存 Family への**合流**)とは別物として併存させる。
  - `linkChild(A, C, options)` — 既存人物を子として帰属させる。既に実装済みだが UI 呼び出し口がゼロの `addChildLink`(`src/domain/commands.ts:99`)に、`addChild` と同じ相方推定(`findSoleSpouseId`)を付けた経路として接続する。これにより**養子縁組を後から記録する**手段が初めて UI に現れる。
  - `linkParent(C, P)` — 既存人物を親とする。ひとり親 Family があればそこへ合流し、**親が既に持つ Family が1件ならその子として加え**、どちらでもなければ新設する。親側の Family を見ずに新設すると、同じ夫婦の Family が二重になり「配偶者未登録」の枠が生まれるため(design.md D8)。
  - 既に親 Family を持つ人物への2つ目の親リンクは、続柄種別を「実子」ではなく「不明」で記録する。実の親が2組いる状態を作らず、養子・継子のどれかは利用者が続柄の編集で確定する(design.md D9)。

### 2. 関係を外す操作を追加する(繋ぎ変えの前半)

- `unlinkChild(F, C)` — 親子リンクを外す。解除の導線は `PedigreeEditor`(子として属する家族の一覧)の各行に置く。
- `unlinkSpouse(F, P)` — 家族から自分だけ配偶者として抜ける。導線は `FamilyEventEditor` の各家族に置く。「配偶者を誤って紐づけたが、子の帰属は正しい」ケースで、家族ごと削除せずに直せるようにする。
- いずれも、外した結果 Family が意味を成さなくなる場合(配偶者0件、または配偶者1件かつ子0件)は当該 Family を削除する。既存の不変条件(`family-data-model`「家族(婚姻単位)の表現」)をそのまま適用する。
- 失われる婚姻・離婚の記録と子の帰属の件数は、実行前に提示して確認を求める。**予告と実行は同一判定に基づかせる**(既存の `isVacantFamily` / `planFamilyRemoval` を共有し、`computeRemovalImpact` と同型の `computeUnlinkImpact` を置く)。

この 1 と 2 の組み合わせにより、「子として作ってしまった人物を配偶者へ繋ぎ変える」が**人物データを一切失わずに**行えるようになる。

### 3. 図に現れていない人物を可視化する(未接続トレイ)

関係を持たない人物は、既定の折りたたみ表示では `main_id` から到達できず**画面上に一切現れない**。非表示人数バッジ(`computeHiddenCounts`)も可視人物の隣接からしか数えないため対象外になる。上記1・2を入れると、追加した人物や解除した人物がそのつど視界から消えることになり、操作が成立しない。

- キャンバス下部に「まだ図に現れていない人物」のトレイを追加する。対象が0人のときは表示しない。
- 対象の定義は「**現在描画されておらず、かつ描画中のどの人物からも関係をたどって到達できない人物**」とする。これにより、関係を持たない人物と、本体から切り離された家族クラスタ(例: 先に登録した夫婦2人)の両方を同一の規則で拾える。全体表示モードでは全人物が描画されるため、トレイは自動的に空になる。
- 既存の非表示人数バッジと合わせて、**非表示の人物は必ずどちらかで示される**という網羅性を要件化する。バッジ = 可視の誰かから辿れる非表示、トレイ = どこからも辿れない非表示、という分担になる。
- トレイの人物はクリックで選択でき、通常の編集パネルが開く。ドラッグ&ドロップによる接続は今回の範囲に含めない(family-chart の座標系に手を入れる必要があるため)。

### 3.5 婿養子(同じ家族の子どうしが夫婦)の重複描画を解消する

同じ Family に子として属する2人が互いに配偶者でもある構成(婿養子・嫁養子)では、描画ライブラリが子ごとにその配偶者を横へ添えるため、**その夫婦と子孫がまるごと2度描かれる**。一方だけを親からの子の辺として描き(実子の側を残す)、他方はその配偶者として描くことで解消する。この間引きは描画の辺にのみ適用し、どの Family の子かという記録や主たる親家族の判定は変えないため、養子として入った家が既定の視点であり続ける(design.md D10)。

あわせて、関係の変更で選択中の人物の最上位祖先が変わった場合に折りたたみ表示の視点を追従させる。追従しないと、既存の人物を親として紐づけてもその親が図に現れないままになる(design.md D11)。

### 4. 不整合なデータを作らせないガード

任意の既存人物を関係先に選べるようになるため、link 系コマンドに以下のガードを設ける。

- 自分自身を親・子・配偶者にできない
- **自分の祖先を自分の子にできない**(世代方向の循環の禁止)。いとこ婚のような無向グラフ上の閉路は正当な家系であるため禁じない。

破壊的変更はない。既存データの読み込み時に自動的な削除・書き換えは行わない。

### 競合製品との比較

Gramps・Family Tree Maker 等のデスクトップ系家系図ソフトは、人物リストと家族エディタが分離しており「人物を先に登録して後から家族に所属させる」ことが標準である。Ancestry・MyHeritage 等の Web サービスも、続柄追加時に "Select existing person" を提供している。本変更は**この水準に追いつくもの**であり、加えて次の2点を上乗せする。

- 関係の解除時に「失われる婚姻・離婚の記録と子の帰属」を件数付きで事前提示する(競合は確認なし、または内容を示さない確認が一般的)。
- 未接続の人物を**キャンバス上のトレイとして常に見える場所に置く**。人物リストを別画面へ分離せず、「図の上で家族を育てる」という本アプリの操作モデル(design D7)を壊さないための選択。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `family-data-model`: 「既存の家族への配偶者の追加」を拡張し、既存人物同士を新しい Family として結ぶこと、既存人物を子・親として帰属させること、および**関係リンクを外すこと**を要件化する。外した結果に対する既存の不変条件(意味を成さない Family を保持しない)の適用と、世代方向の循環を作らせない制約を追加する。
- `tree-editor`: 「キャンバスからの関係追加」に、関係を指定しない人物追加と「既存の人物から選ぶ」経路を追加する。「人物・関係の削除」に、人物を削除せず関係リンクのみを外す操作と、その事前提示(予告と実行の一致)を追加する。
- `tree-rendering`: 「非表示人数バッジ」に隣接して、図に現れていない人物のトレイを要件化する。バッジとトレイで非表示の人物を漏れなく分担することを明記する。あわせて、同じ Family の子どうしが夫婦である場合(婿養子)の重複描画の回避と、関係の変更にともなう視点の追従を要件化する。

**プライバシー・法務**: 影響なし。すべてクライアント内で完結する編集操作・描画であり、外部送信は発生しない。戸籍データの流れは変わらない。生成物の位置づけ(観賞用・記念用)にも変更はない。

**ロールバック方針**: 単一 PR の revert で完結する。データ形式を変更せず、読み込み時のマイグレーションも行わないため、revert 後も本変更適用中に編集したデータはそのまま読める。ただし revert 後は、本変更で作った「関係を持たない人物」が既定の折りたたみ表示から見えなくなる(全体表示モードでは引き続き表示される)。データとしては失われず、GEDCOM/JSON エクスポートにも含まれ続ける。

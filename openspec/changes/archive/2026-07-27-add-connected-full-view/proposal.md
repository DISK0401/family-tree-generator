# add-connected-full-view

## Why

全体表示モードは「記録されている家系全体を1枚の図に表示する」ことを謳っているが、実際には**家ごとのブロックに分かれて並ぶ**。婚姻でつながった2つの血族(例: 夫の実家と妻の実家)が1枚の図としてつながらない。

原因は描画ライブラリ family-chart のレイアウト構造そのものにある。`calculateTree` は `main_id` を根とする**2本の d3.hierarchy**(祖先方向・子孫方向)しか作らず、配偶者は `setupSpouses` が木の外側に手で座標を付けて添えるだけで、**d3.hierarchy の一部ではない**。したがって配偶者の祖先・傍系は原理的にレイアウトされない。現在の全体表示は仮想ルートとスタブカードでこれを回避しているが、根が「血縁で連結した範囲」ごとに立つため、家ごとのブロックになるのは必然の帰結である。

fork せずに解決できないかを実測した(`docs/research/2026-07-family-chart-hooks-spike.md`)。結論は次のとおり。

- `setDuplicateBranchToggle` は子孫側しか畳まず、目的に無関係
- `setModifyTreeHierarchy` は2つの血族を**正しい世代位置へ並べられる**が、配偶者とその実家を結ぶ**系線が引かれない**。系線生成そのものへ手を入れる必要があり、埋めるコストは自前レイアウトと変わらない

したがって、全体表示のレイアウトを自前で持つ。fork は選ばない。上流のフックは目的に足りず、fork してレイアウトを書き換えるなら family-chart の外で書くのと手間が変わらないためである。

影響範囲は**無料版のみ**。クライアント完結の描画の変更であり、有償版・サーバ通信・戸籍データの流れには一切関与しない。

## What Changes

### 1. 系図レイアウタを新設する

`TreeDocument` から座標付きの図(人物の配置と系線)を直接求める、family-chart に依存しないレイアウタを追加する。婚姻を**第一級の結合**として扱うことで、婚姻でしかつながらない血族どうしを1枚の図に収める。

処理は次の3段とする。

1. **世代の割り当て** — 親子関係を制約として各人物を層へ配置する。婚姻する2人は同じ層に置く
2. **層内の順序決定** — 家族(夫婦)単位でまとめ、系線の交差を減らす向きに並べる
3. **座標の割り当て** — 夫婦は隣接、子は両親の中央下へ置く

同一人物を複数箇所に複製しない。実親・養親の双方を持つ人物も1箇所に置き、複数の親家族からの系線を引く(family-chart では表現できずスタブカードで代替していた点が、ここで解消される)。

### 2. 「つながった全体表示」を新しい表示モードとして追加する

キャンバスの表示モードを3つにする。

| モード | 描画 | 用途 |
|---|---|---|
| 折りたたみ表示(既定) | family-chart | 対話的な編集。**変更しない** |
| 全体表示(家ごと) | family-chart | 家系ごとに分けて俯瞰する。**現状の挙動を維持する** |
| **つながった全体表示(新規)** | 自前レイアウタ | 記録されている全員を1枚の図でつなげて俯瞰する |

折りたたみ表示は今回いっさい変更しない。スパイクで、対話的な編集面としては family-chart がよく機能していることを確認しているためである。既存の全体表示も、家系ごとに見たい場面で有用であるとの利用者の判断により残す。

### 3. カードの見た目を2つの描画系で揃える

縦書き明朝の氏名・性別の色と形状・現年齢/没年齢・故人マーカーといった人物カードの表現は、現在 `FamilyTreeCanvas` の `setCardInnerHtmlCreator` の中に閉じている。自前レイアウタ側でも同じ見た目を出せるよう、カードの内容を組み立てる部分を描画系から独立させて共有する。表示設定(生没日の粒度・和暦/西暦・表示項目の選択)も両方の描画系へ等しく効くようにする。

### Non-Goals

- **折りたたみ表示の置き換え**。family-chart のまま据え置く
- **family-chart の fork**。今回は行わない。将来ライブラリ側へ踏み込む要求が溜まった時点で改めて判断する
- **PDF・巻物出力**。ただし本レイアウタはその土台になる形にする(印刷用の1枚レイアウトは同じ問題を解く)
- **自前レイアウタ上での編集操作**。カードの選択(編集パネルを開く)までとし、関係の追加・解除は折りたたみ表示側の導線を使う

### 競合製品との比較

Gramps・Family Tree Maker 等のデスクトップ系家系図ソフトは、家族(FAM)を1つのレイアウト単位として扱う層別レイアウトを持ち、婚姻でつながる複数の血族を1枚の図に描ける。国内の「みんなの家系図」等の Web サービスも直系中心の1枚表示を提供している。現在の本アプリはこの点で見劣りしており、本変更は**同等水準に追いつくもの**である。

加えて次の2点を上乗せする。

- 実親・養親の双方を持つ人物を**複製せずに1箇所へ置き**、複数の親家族からの系線を引く(現在のスタブによる複製表示の解消)
- 3つの表示モードを利用者が切り替えられる。「家系ごとに分けて見る」か「全部つなげて見る」かを選べる家系図サービスは調査範囲では見当たらない

## Capabilities

### New Capabilities

- `pedigree-layout`: `TreeDocument` から座標付きの系図(人物の配置と系線)を求めるレイアウタ。描画ライブラリに依存しない純粋な計算として定義し、将来の印刷・PDF 出力からも同じ結果を再利用できるようにする。

### Modified Capabilities

- `tree-rendering`: 「全体表示モード」を拡張し、家系ごとに分ける従来の表示に加えて、婚姻でつながる血族を1枚に収める「つながった全体表示」を要件化する。3つの表示モードの切り替えと、カード表現・表示設定が描画系によらず一致することを明記する。

## Impact

- `src/layout/`(新規)— 系図レイアウタ。世代の割り当て・層内の順序決定・座標の割り当ての3段と、その単体テスト
- `src/rendering/PedigreeCanvas.tsx`(新規)+ CSS — レイアウタの結果を SVG として描画するコンポーネント。カードの選択のみを扱う
- `src/rendering/person-card.ts`(新規)— カードの内容(縦書きの氏名・性別・年齢・故人マーカー)の組み立てを `FamilyTreeCanvas` から切り出し、2つの描画系で共有する
- `src/rendering/FamilyTreeCanvas.tsx` — 表示モードの切り替えを2値から3値へ。折りたたみ表示・既存の全体表示の挙動は変更しない
- `README.md` — 表示モードの記述更新(タスクとして扱う)

依存追加なし。d3 は family-chart の依存として既に入っており、レイアウタが d3 の階層・尺度ユーティリティを使う場合も新規の依存にはならない(直接依存として明示するかは design で決める)。

永続化スキーマ(`SCHEMA_VERSION`)は 1 のまま据え置く。レイアウトは `TreeDocument` からの導出であり、保存する情報は増えない。

**プライバシー・法務**: 影響なし。すべてクライアント内で完結する描画の追加であり、外部送信は発生しない。戸籍データの流れは変わらない。生成物の位置づけ(観賞用・記念用)にも変更はない。

**ロールバック方針**: 単一 PR の revert で完結する。データ形式を変更せず、既存の2つの表示モードにも手を入れないため、revert すると新しい表示モードが消えるだけで、既存の描画・保存データは一切影響を受けない。

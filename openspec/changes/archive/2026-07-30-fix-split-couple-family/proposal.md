# fix-split-couple-family

## Why

利用者から2件の報告があった(いずれも同一の家系図データ)。

- 富岡徳雄・ぎん夫婦の子であるはずの 榮 が、夫婦の婚姻線からではなく**徳雄から直接**系線が伸びる。「親を追加」の操作で起きている気がする
- 同様に、齋藤兎一・富岡榮夫婦の子(紀佳・洋公・英子)が**すべて兎一から**伸びてしまう

報告されたJSONを実際のコマンド列で再現したところ、描画は記録されたデータを忠実に描いており、**データの側が本当にひとり親のFamilyになっていた**。

```
報告データ(抜粋)
  Family{ 配偶者=[徳雄],     子=[榮] }          ← ぎんが親として記録されていない
  Family{ 配偶者=[徳雄, ぎん], 子=[兎一] }

  Family{ 配偶者=[兎一],      子=[] }           ← 空き殻(旧バージョンの残留)
  Family{ 配偶者=[榮, 兎一],   子=[] }           ← 婚姻。子が1人もいない
  Family{ 配偶者=[兎一],      子=[紀佳] }        ┐「親を追加」のたびに
  Family{ 配偶者=[兎一],      子=[洋公] }        │配偶者不在のFamilyが
  Family{ 配偶者=[兎一],      子=[英子] }        ┘新設されていた
```

原因は2つある。

### 原因1: `linkParent` の帰属先判定が、婚姻でないFamilyの件数に引きずられる

「既存の人物を親としてリンクする」際の帰属先は、spec `family-data-model`「既存人物同士の関係リンク」の規則2で「親となる人物が配偶者として属するFamilyがちょうど1件の場合は、そのFamilyの子として加える」と定めている。この件数は**婚姻でないFamilyも数える**。

報告データの兎一は、榮との婚姻に加えて配偶者1件・子0件の**空き殻Family**を持つ。これは `fix-spouseless-family-handling` 以前のバージョンが残したもので、同changeのD3が「読み込み時の自動修復は行わない」と決めているため保存済みドキュメントには残りうる。この1件のせいで件数が2件になり規則2が働かず、「親を追加」のたびに配偶者不在のFamilyが新設され、夫婦の子が兎一だけの子として記録された。

規則2の目的は「親に既に配偶者がいるのに配偶者不在のFamilyを新設しない」ことなので、数えるべきは**親の婚姻(配偶者2件のFamily)**であって、親が属するFamilyの総数ではない。

### 原因2: 同じ夫婦のFamilyが二重に作られうる

`linkSpouse` は「同一カップルの復縁は1つのFamilyのイベントとして表現する」ため、既に配偶者である相手との2件目のFamily作成を拒否する。ところが**既存のFamilyへ2人目の配偶者を加える経路**(`addSpouseLink` と `linkParent` の規則1)にはこの検査がなく、同じ夫婦のFamilyが2件並ぶ状態を作れてしまう。

これが徳雄・ぎんの件の修復導線を塞いでいる。`fix-spouseless-family-handling` が用意した「配偶者に既存の人物を設定」で `Family{ [徳雄], 子=[榮] }` へ ぎん を紐づけると、徳雄・ぎんのFamilyが2件になり、子は2件に分かれたままになる。同changeのD7は「紐づけ後に残る重複Familyは削除導線で利用者が消す」としていたが、**双方に子がいる場合は削除すると子の帰属が失われる**ため、この手当てでは直せない。

### 影響範囲

**無料版のみ**。変更は `src/domain/commands.ts` の編集コマンド(クライアント内の純関数)に閉じる。ネットワーク送信・外部API呼び出しは発生せず、`local-autosave` の「外部送信ゼロ」を維持する。保存形式(`SCHEMA_VERSION`)・GEDCOM/JSONの入出力・描画コードには変更がない。戸籍画像や要配慮個人情報の流れは一切変わらないため、プライバシー・法務への新たな影響はない。

## What Changes

### 1. `linkParent` の帰属先を「親の婚姻」で判定する

規則2の判定対象を、親が配偶者として属するFamilyの総数から、**親の婚姻(配偶者2件のFamily)の件数**へ変える。婚姻が1件に定まらない場合は、従来どおり「親が属するFamilyがちょうど1件ならそこへ」を経て、どれにも当てはまらなければ親のみのFamilyを新設する。再婚等で婚姻が2件以上ある場合に推測しない点は変えない。

これにより、空き殻やもう一方の親が不明なひとり親のFamilyが残っていても、「親を追加」した子は夫婦のFamilyへ入る。

### 2. 同じ夫婦のFamilyが二重になる場合は1件へ統合する

既存のFamilyへ2人目の配偶者を加えた結果、その2人を配偶者とするFamilyが既に別にある場合、子と婚姻・離婚イベントを既存のFamilyへ移して**1件へ統合する**。`addSpouseLink` と `linkParent` の規則1が対象。

統合が足す事実は「その2人が夫婦である」という利用者がその操作で明示した内容だけであり、推測で親子関係を作らない原則(`fix-spouseless-family-handling` D5)には抵触しない。

これにより、既に分裂して保存されている家系図を、利用者が**報告時と同じ「親を追加」の操作で**修復できる。

- 榮 に「親を追加」で ぎん を選ぶ → `Family{ [徳雄], 子=[榮] }` が `Family{ [徳雄, ぎん], 子=[兎一] }` へ統合され、榮 と 兎一 が同じ夫婦の子になる
- 紀佳・洋公・英子 に「親を追加」で 榮 を選ぶ → それぞれの `Family{ [兎一], 子=[…] }` が `Family{ [榮, 兎一] }` へ統合される

新しいUIは追加しない。既存の「親を追加 → 既存の人物から選ぶ」と、婚姻・離婚の編集面の「配偶者に既存の人物を設定」がそのまま修復導線になる。

## Impact

- **spec**: `family-data-model`(「家族(婚姻単位)の表現」「既存の家族への配偶者の追加」「既存人物同士の関係リンク」)、`tree-editor`(「配偶者が未登録の家族への既存人物の紐づけ」「既存の人物を関係先に選ぶ」)
- **コード**: `src/domain/commands.ts`(`linkParent` / `addSpouseLink`)。UI・描画・永続化は変更なし
- **既存データ**: 保存済みドキュメントの自動修復は行わない(`fix-spouseless-family-handling` D3 を踏襲)。分裂したまま保存されているデータは、利用者の操作で修復する
- **挙動の変化**: `addSpouseLink` が、同じ夫婦のFamilyが既にある場合にFamilyを1件へ統合するようになる。統合の結果、紐づけ先として指定したFamilyのIDは消え、既存の夫婦のFamilyが残る

## Rollback

変更は `src/domain/commands.ts` の2関数に閉じており、revertでコマンドの挙動は即座に元へ戻る。保存形式を変えないため、新しい挙動で保存されたドキュメントは旧バージョンでもそのまま読み込める(統合されたFamilyは、旧バージョンから見ても正当な「配偶者2件・子あり」のFamilyである)。revertによって失われるのは統合機能だけで、統合済みのデータが壊れることはない。

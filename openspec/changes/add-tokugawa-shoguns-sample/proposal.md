# add-tokugawa-shoguns-sample

## Why

現在の偉人家系図サンプル4種はいずれも**10人前後の小規模**で、見せたいパターン(複数配偶者・養子縁組・再婚・三世代)を1つずつ最小構成で示すものになっている。そのため次の2点が確認できない。

1. **多世代・多分家の実データで図と入力面が実用に耐えるか。** 15世代規模の縦長の系図、分家からの継承で系線が世代をまたぐ構成、数十人規模での自動整列・つながった全体表示の可読性は、現状のサンプルでは体験できない。
2. **和暦の幅。** 既存サンプルの和暦は明治以降か単発の旧暦のみで、戦国期(天文)から大正までの元号をまたぐ表示・入力の確認ができない。

徳川将軍15代は、この2点をまとめて満たす題材である。将軍職の継承が実子相続ばかりではなく、**甲府家・紀州家・一橋家・水戸家からの入嗣**で繋がっており、養子縁組・分家・世代をまたぐ継承という本アプリが表現の主眼に置く構造がそのまま現れる。全員が故人で、系譜はWikipedia等で公知であり、サンプルの人選条件(`sample-tree-gallery` spec)を満たす。

あわせて、新しく追加した**表形式ビューの一括入力の実用検証**(数十人規模の書き写し・並べ替え・絞り込み)の題材としても使える。

影響範囲は**無料版のみ**。静的なサンプルデータの追加であり、有償版・サーバ通信・戸籍データの流れには一切関与しない。

## What Changes

### 1. サンプル「徳川将軍15代」を追加する

`/app?sample=tokugawa-shoguns` で開ける新しいサンプルを追加する。収録範囲は次のとおり。

- **将軍15代**(家康〜慶喜)全員
- **系譜を繋ぐ分家の当主**: 紀州徳川家(頼宣・光貞・斉順)、甲府徳川家(綱重)、一橋徳川家(宗尹・治済)、水戸徳川家(頼房・光圀・綱條・宗堯・宗翰・治保・治紀・斉昭)、高松松平家(頼重)
- **主要な正室2名**(崇源院・天璋院)

計32名(将軍15名 + 分家の当主15名 + 正室2名)。
- 生没日は和暦の原文を保持し、明治6年の改暦以前(旧暦)は年のみを構造化日付とする(既存サンプルと同じ方針)
- 養子縁組は実際の入嗣関係として記録する(例: 家宣=綱重の実子かつ綱吉の養子、綱條=松平頼重の実子かつ光圀の養子、家茂=斉順の実子かつ家定の養子)

### 2. 既存の「徳川家康」サンプルは変更しない

`tokugawa-ieyasu`(複数配偶者を最小構成で見せる10人)はそのまま残す。役割が異なり(あちらは複数配偶者の最小例、こちらは多世代・分家継承の大規模例)、既存のテスト・E2Eも参照しているため。

### Non-Goals

- **16代以降(明治以降の宗家当主)の収録**。第18代当主が現存されるため、`sample-tree-gallery` spec の「実在の存命人物は扱わない」に触れる。江戸期の15代で打ち止めとする。
- **皇室出身の人物の収録**。同 spec が「皇室系譜を扱ってはならない(MUST NOT)」と定めるため、14代家茂の正室である和宮親子内親王(仁孝天皇の皇女)は収録しない(故人だが皇族であり、収録すると制約に触れる)。
- **将軍の子女・側室の網羅**。継承の系統を追うのに必要な人物と主要な正室に限定する(網羅すると数百人規模になり、サンプルとして読めない)。
- **既存サンプルの置き換え・統合**。
- **史料考証**。Wikipedia等の公知情報に依拠し、諸説ある事項は深追いしない(サンプル注記でその旨を示す)。

## Capabilities

### New Capabilities

(なし)

### Modified Capabilities

- `sample-tree-gallery`: 収録するサンプルの一覧に「徳川将軍15代」を追加する(サンプルの本数と、各サンプルが見せるパターンの定義が変わる)。

## Impact

- **プライバシー・法務**: 影響なし。静的データの追加のみで、外部送信ゼロ・IndexedDB保存の方針は不変。収録人物は全員故人で系譜は公知(`sample-tree-gallery` spec の人選条件に適合)。出典は公知情報であることをサンプルのメモに明記する。
- **コード**: `src/samples/data/tokugawa-shoguns.ts`(新規)、`src/samples/sample-meta.ts`・`load-sample.ts`(サンプル一覧への追加)、`src/pages/landing/`(ギャラリーのタブが1つ増える)。ドメイン・描画・永続化・入出力のロジックは変更しない。
- **バンドル**: サンプルデータは動的importで分割済みのため、エディタ・ランディングの初期ロードには影響しない(新しいチャンクが1つ増えるだけ)。
- **テスト**: 既存の「サンプル4種すべてをzodスキーマと参照整合性で検証する」テストが自動的に新サンプルも対象にする。加えて、収録人数・世代数・養子縁組の存在を確認するテストと、レイアウト不変条件(カードの重なり・系線の非交差)の検証を追加する。
- **README**: サンプル一覧の表に1行追加する。

## ロールバック方針

静的データとその参照の追加のみで、データモデル・保存形式・入出力形式の変更を伴わない。問題が出た場合はサンプル一覧から当該IDを外す(または change を revert する)だけで、既存機能・既存サンプルに影響なく戻せる。利用者が既に読み込んだデータは通常のTreeDocumentとして端末に残る。

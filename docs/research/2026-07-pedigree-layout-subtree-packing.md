# つながった全体表示のレイアウト: subtree packing の検討メモ(2026-07)

`add-connected-full-view` の実装中に「一族が他の一族の真上に来て読みにくい」という指摘を受け、
**一族ごとに横幅を確保して並べる(subtree packing)**方式を検討したが、この change の範囲としては
大きすぎるため見送った。100名規模を扱うようになったときに再開できるよう、そのときの判断材料を残す。

- 対象: `src/layout/`(`layoutPedigree`)
- 現状の方式: 層ごとに独立して詰め、上下方向の緩和で親子を寄せる(design.md D2-3)
- 見送った理由: 32名規模では現在の方式で読めるところまで改善できたため。ただし**規模が増えると不利になる**(下記)

## 何が起きていたか

実データ(32名・5世代)で、新井イツ子・定夫の一族(層1に3名)が、富岡家のきょうだい(層2に14名)の
真上に重なって表示され、どちらの一族の人物か読み取りにくかった。

原因は層ごとの人数差である。

| 層 | 人数 | 幅(カード104px + 間隔24px) |
|---|---|---|
| 層0 | 8 | 1,000px |
| 層1 | 5 | 616px |
| 層2 | 13 | 1,640px |

層1は層2より必ず狭くなるため、層1の右端にいる新井の一族は、層2の右端にいる富岡薫より必ず左に来る。
**層ごとに詰めるかぎり、一族を横方向に分離することは原理的にできない。**

この change では緩和の重み付けを調整して重なりを解いた(下記「現在の緩和で入れた対策」)が、
一族を分離しているわけではないため、人数が増えると再発しうる。

## subtree packing とは

各人物に「その人物の子孫が占める横幅」を持たせ、**幅ぶんの領域を確保してから兄弟どうしを横に並べる**。
Reingold–Tilford の tidy tree 描画を家族単位へ広げたものにあたる。

```
現在(層ごとに詰める)              subtree packing
─────────────────                ──────────────
層0: [A夫婦][B夫婦]               層0: [A夫婦        ][B夫婦   ]
層1: [Aの子ら][Bの子ら]           層1: [Aの子ら      ][Bの子ら ]
層2: [Aの孫が大量に……]           層2: [Aの孫が大量に][Bの孫   ]
      ↑ Bの子らがAの孫の真上に来る      ↑ 一族が横方向に分離する
```

## 難しさ: 家系図は木ではない

この change の出発点そのものだが、家系図は**木ではなくグラフ**である(婚姻で複数の血族が結ばれ、
養子縁組で1人が複数の親を持つ)。subtree packing は「各人物がちょうど1つの親を持つ」木を前提とするため、
そのままでは適用できない。

- **婚入**: 新井美和は「新井家の子」であり同時に「富岡佳彦の配偶者」でもある。どちらの一族のブロックに
  属させるかを決めなければならず、選ばれなかった側の系線は長く伸びる
- **養子縁組**: 齋藤兎一は齋藤家の実子であり富岡家の養子でもある。同上
- つまり **主たる所属を1つ選ぶ(= 全域木を取る)** 必要があり、family-chart が抱えていた
  「木を前提にしているため婚姻を結合として扱えない」問題に、形を変えて再び触れることになる

## トレードオフ

| | 現在(層ごとに詰める) | subtree packing |
|---|---|---|
| 一族の見分けやすさ | 一族が他の一族の真上に来ることがある | 一族が横方向に分離する ✅ |
| 図の横幅 | 必要最小限 | 大きく広がる(各一族が最大幅を占有) |
| 婚姻をまたぐ系線 | 現状程度 | さらに長くなる |
| 実装 | 済み | 新しい段(ブロックの幅の計算とパッキング)が要る |

**100名規模で効いてくる点**: 世代が下るほど人数が増えるため層ごとの人数差は開き、重なりは増える。
一方で図の横幅も加速度的に広がるため、subtree packing を入れる場合は
「横幅が広がりすぎないための折りたたみ・間引き」とセットで考える必要がある。

## 再開するときの入り口

1. `src/layout/ordering.ts` — 層内の並び順を決める段。ここまでは流用できる
2. `src/layout/coordinates.ts` の `assignCoordinates` — **ここを差し替える**。現在は層ごとに
   PAVA(単調非減少制約下の最小二乗当てはめ)で詰めているが、subtree packing ではブロックの幅を
   下の層から積み上げてから配置する
3. 主たる親家族の選び方は `findPrimaryParentFamily`(`src/rendering/to-family-chart-data.ts`)が
   既に持っている(非実子を優先する規則)。全域木を取る際はこれを流用できる
4. 系線のレーン割り当て(`assignLinkLanes`)はそのまま使える。むしろブロックが分離するぶん
   必要なレーン数は減る

検証には、報告のあった実データ(32名・婿養子と3世代下への婚入を含む)が最小の再現例として使える。
個人情報のためリポジトリには置いていない。

## 現在の緩和で入れた対策(subtree packing なしで到達した範囲)

再開時に「すでに手当てされていること」として踏まえる。

- 層内の並び替えで、基準にする相手を**隣の層に限定しない**(実家が2層以上離れた婚入者が層の末尾へ
  固定される問題への対策)
- 並びの評価を「交差数を最優先、同数なら系線の長さの総量」にした(交差数だけでは図を横断する
  長い系線に差が付かない)
- x座標の緩和で、**層が離れた相手ほど弱く引く**(重みは層の隔たりの逆数)。3層下へ嫁いだ子に
  等しく引かれて実家ごと他家の真上へ入り込む問題への対策
- 親子線の横に走る区間を**子のいる層のすぐ上の隙間**へ置き、横方向に重なる束には別のレーンを割り当てる
